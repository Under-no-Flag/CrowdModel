## 2. 当前实验目标

当前阶段的实验目标不是直接完成完整优化研究，而是先完成一个可复现、可解释、可扩展的实验闭环，具体包括：

1. 验证模型中的核心机制是否真的改变了人群的局部决策与流动形态，并且这种改变与真实场景中的行为特征一致：
   - 几何引导 `M(x)` 是否改变局部方向偏好、接近角和通道吸引域
   - 方向约束 `U(x)` 是否改变局部最优方向、转向时机和通道选择结构，并在双向来流下抑制逆行与迎面对冲
   - 多阶段固定概率分流是否改变阶段切换、局部汇聚与离场路径组织
2. 比较不同通道管控策略在效率、安全与均衡性上的差异。
3. 验证多阶段行为链是否会改变阶段密度演化。
4. 完成当前论文版最优控制参数求解设计，使控制变量能够进入 HCMBO 自动搜索而不是只靠手工挑选，其中控制变量由通道方向配置 `s` 与入口流量控制 `q(t)` 共同构成，方向变量需覆盖正向、反向、双向和关闭四类状态。
5. 为下一阶段的参数敏感性、鲁棒性和完整优化器实现提供标准化实验接口。

## 3. 第一阶段范围冻结

### 3.1 本周正式纳入实现与实验的内容

- 固定概率分流
- 共享拥堵速度函数 `f(\rho^{tot})`
- 三通道主场景
- 多阶段游览场景
- Bellman 统一求解框架
- 核心指标统计与结果汇总
- 当前论文版最优控制参数求解：
  - 面向 `z=(s,q)` 的 HCMBO 求解器
  - `s` 离散邻域搜索，覆盖正向、反向、双向和关闭四类通道状态
  - `q(t)` 分段入口流量控制搜索
  - 代理预筛选、接受/回退和历史最优解维护
  - 随机搜索、TPE、DE 等横向基线对照

### 3.2 本周只做设计、不进入正式实现的内容

- 真实数据标定
- Logit 概率分流
- 专门 Godunov kernel 与统一 Bellman 求解器的数值对照
- 大规模鲁棒性与应急场景扩展

### 3.3 第一阶段边界说明

因此，第一阶段的实验结论应限定为：

- 证明当前模型框架具备表达管控机制的能力；
- 证明不同通道策略之间存在可量化差异；
- 证明多阶段行为会改变负载分配；
- 完成 HCMBO 在当前论文变量边界 `z=(s,q)`、`p=\hat p` 固定条件下的实现与对比实验，并通过横向基线和内部消融说明其求解行为；不宣称已经完成真实场景标定或完整 Pareto 前沿求解。

## 4. 场景与实验对象

## 4.1 场景 A：三通道主场景

该场景用于机制验证和主策略对比。其几何和实现基础来自当前 `codes/crowd_bellman/scenes.py` 中的三通道场景生成逻辑。

### 场景特征

- 左侧为初始人群区域
- 右侧为出口区域
- 中部隔墙上设置上、中、下三条通道
- 可在通道及其引导区域上施加：
  - 几何引导张量 `M(x)`
  - 单向方向约束 `U(x)`

### 当前已有 case

- `case1_baseline`
- `case2_middle_guided`
- `case3_top_guided`
- `case4_bottom_guided`

### 当前仍需补充的机制 case

- `M-only` case：仅有几何引导，无单向约束
- `U-only` case：仅有单向约束，无几何引导

这两个 case 主要服务于实验组 1，不要求 Day 1 当天实现，但必须在设计中预留。

## 4.2 场景 B：多阶段游览场景

该场景用于多阶段分流行为验证。其实现基础来自当前 `case5_multistage_tour`。

### 场景特征

- 左侧区域为起始集聚区
- 人群先进入右侧平台区域
- 在平台内按阶段变化目标
- 在离场阶段按固定概率分流到不同出口通道
- 最终返回左侧出口

### 当前已有 case

- `case5_multistage_tour`

### 当前需要补充的对照 case

- 单阶段近似 case：忽略阶段转换与分流，将目标近似为单一出口
- 无分流 case：保留阶段但仅设置单一路径

这些对照 case 不再用于论证“分流概率值得被优化”，而是用于识别：

- 多阶段行为层本身是否有必要保留；
- 偏好参数 `p` 是否应作为外生行为结构被识别和固定；
- 若忽略这些行为结构，后续对可控策略的评估是否会失真。

## 7. 各实验组正式设计

## 7.1 G1：模型机制验证

### 目标

G1 不再以“某个机制是否提升系统指标”为第一目标，而是回答两个更基础的问题：

1. 机制真实性：
   - `U(x)` 和 `M(x)` 是否真的改变了人群在局部的“怎么走、何时转向、朝哪个通道靠拢”；
   - 这种改变是否与外滩通道场景中可观察到的行为特征一致。
2. 管理可用性：
   - 当通道方向配置或引导配置改变时，模型是否会产生足够敏感、足够可解释的行为响应；
   - 如果机制错误或过于生硬，后续优化是否会落在错误的人群行为模型上。

因此，G1 的任务是先证明模型“行为上可信、配置上敏感”，再谈它能否作为优化器的评估器。

### 研究问题

1. 单向规则 `U(x)` 是否真的重塑了通道口附近的局部最优方向、转向方式和通道选择结构？如果引入双向来流，它是否还能抑制中通道逆行与迎面对冲？
2. 各向异性 `M(x)` 是否改变了通道口周围的接近角、提前对齐距离、流线弯折方式和通道吸引域？
3. `U+M` 联合作用下，模型是否能对不同通道配置给出既符合规则、又具有真实局部流型的行为响应？
4. 如果去掉 `U` 或 `M` 其中之一，后续策略比较与优化评估是否会建立在失真的行为机制之上？

### 对比 case

| 机制主线 | 方案 | 说明 | 当前状态 |
|------|------|------|------|
| A0 | `case1_baseline` | 单向来流基线，无 `U`，无 `M` | 已有 |
| A1 | `U-only` case | 单向来流下仅启用单向约束，用于看规则是否改变局部方向组织与通道选择 | 已有 |
| A2 | `case_u_bidirectional_baseline` / `case_u_bidirectional_middle_rule` | 双向来流下的 `U` 对冲抑制对照，用于直接检验是否压制中通道逆行与迎面对冲 | 本次补充 |
| B0 | `case1_baseline` | 基线，无各向异性引导 | 已有 |
| B1 | `M-only` case | 仅启用几何引导，用于看接近与转向形态是否变化 | 已有 |
| C0 | `case1_baseline` | 无 `U`、无 `M` 的配置敏感性基线 | 已有 |
| C1 | `U-only` case | 只有规则，无几何引导 | 已有 |
| C2 | `case2_middle_guided` 或新建 `M+U-middle` | `U+M` 联合模型，中通道双控 | 已有基础，可直接使用或细分 |
| C3 | `case5_multistage_tour` | 多阶段行为链展示，用于说明机制验证可自然衔接到行为层 | 已有 |

### 自变量

- 是否启用单向约束 `U`
- 是否启用几何引导 `M`
- 通道方向配置方案
- 各向异性强度或引导参数
- 是否启用多阶段分流机制（作为行为层补充验证）

### 因变量

- 局部最优方向场
- 方向一致性指数 / 逆规则方向占比
- 双向来流下的中通道逆行占比 / 对冲暴露
- 通道吸引域或捕获域
- 接近角分布
- 提前对齐距离
- 流线弯折形态 / 出入口扇形流型
- 关键通道流量占比与局部密度分布

这里的主因变量优先是“行为形态指标”，而不是 `J1/J2/J5`。

### 控制变量

- 场景几何
- 初始密度
- 网格与时间步规则
- 速度函数
- 出口边界与障碍设置
- 观察区域与局部放大窗口
- 统计口径（入口截面、通道轴线、方向场采样方式）
- 单向来流验证与双向对冲验证应分开统计，不混用同一口径

### 主要输出

- 局部方向场图
- 通道吸引域 / 捕获域分区图
- 入口接近角分布图
- 双向来流下的中通道逆行占比 / 对冲暴露对比图
- 局部流线与典型时刻密度放大图
- 机制对比表
- 配置变化下的行为响应对比图

### 判定方式

G1 的判定分成两层：

#### 第一层：机制真实性

- 若 `U-only` 明显改变通道内方向一致性、逆规则方向占比和局部方向图，则说明 `U(x)` 确实改变了局部 Bellman 最优控制；
- 若在双向来流下，加入中通道单向规则后，中通道内的逆行占比、迎面对冲暴露和相向重叠显著下降，则才能进一步说明 `U(x)` 不只是“改路”，而是真的抑制了逆行和对冲；
- 若 `M-only` 明显改变接近角分布、提前对齐位置、流线收敛方式和通道吸引域形状，则说明 `M(x)` 改变的是合法空间内的方向偏好，而不是简单的几何封堵；
- 若这些变化与真实场景经验一致，例如“更早对齐通道轴线”“入口前平滑汇聚而不是临门急转”，则说明机制具有行为合理性。

#### 第二层：管理可用性

- 若切换通道配置后，`U+M` 模型能给出明显、可解释的局部行为重组，则说明该模型足以作为后续策略评估器；
- 若去掉 `U` 或 `M` 后，模型对配置变化的响应变得迟钝、生硬或与场景直觉不符，则说明后续优化不能建立在残缺机制上；
- 因此，G1 的结论不是“先证明 `J1/J2/J5` 更优”，而是先证明“如果机制不对，后续优化就在错误的人群行为模型上做优化”。

## 7.2 G2：管控策略响应与可优化性验证

### 目标

G2 的目标不再是简单回答“哪组策略最好”，而是证明在完整行为模型下：

1. 不同通道配置 `s` 确实会引起可区分、可解释的系统响应；
2. 效率 `J1`、安全 `J2`、均衡 `J5` 之间存在非一致最优，因此后续优化是必要的；
3. 这些响应差异足够稳定，能够形成后续优化器的候选解空间和评估基线。

### 研究问题

1. 在“中通道进场偏好 + 南向游览 + 中通道回流偏好”的多阶段行为基线上，改变三条通道的通行方向设置并允许单条通道关闭后，是否会系统性改变各通道累计流量、峰值负载时刻和高密度区的位置迁移？
2. `J1/J2/J5` 之间是否存在明确 trade-off，而不是由某一个方向设置全面支配？
3. 通道方向设置是否已经形成可排序、可优化的候选解空间，从而说明后续优化器不是装饰而是必要组件？

### 对比 case

| 策略组 | case | 说明 |
|------|------|------|
| S0 | `case1_baseline` | 无方向管控基线。人群偏好从中通道进场，到右侧平台南向游览，再偏好从中通道回流到左侧消失；这里的“偏好”只由阶段目标诱导，不限制通道方向 |
| S1 | `case2_topE_middleW_bottomW` | 只保留一条东向进场通道 `top`，其余两条通道设为西向回流 |
| S2 | `case3_topW_middleE_bottomW` | 只保留一条东向进场通道 `middle`，其余两条通道设为西向回流 |
| S3 | `case4_topW_middleW_bottomE` | 只保留一条东向进场通道 `bottom`，其余两条通道设为西向回流 |
| S4 | `case5_topW_middleE_bottomE` | 只保留一条西向回流通道 `top`，其余两条通道设为东向进场 |
| S5 | `case6_topE_middleW_bottomE` | 只保留一条西向回流通道 `middle`，其余两条通道设为东向进场 |
| S6 | `case7_topE_middleE_bottomW` | 只保留一条西向回流通道 `bottom`，其余两条通道设为东向进场 |
| S7 | `case8_topC_middleE_bottomW` | 关闭 `top` 通道，保留 `middle` 东向进场与 `bottom` 西向回流，用于评估上通道临时封控 |

## 7.3 G3：多阶段行为层必要性与偏好参数识别支持

### 目标

G3 的目标不再是论证“固定概率分流本身值得被优化”，而是证明：

1. 多阶段行为层必须被保留，否则后续策略评估会失真；
2. 偏好参数 `p` 应作为外生行为结构被识别和固定，而不是与可控策略混为一体；
3. 在固定 `p` 的前提下，模型仍然能够支撑后续对可控策略 `s` 与入口流量控制 `q(t)` 的优化。

### 研究问题

1. 与单阶段近似相比，多阶段行为链是否会改变平台滞留、出口负载和热点迁移？
2. 若保留多阶段结构但去掉出口偏好差异，模型输出是否会与完整行为层显著不同？
3. 若忽略多阶段行为层或固定偏好参数 `p`，后续对策略优劣的判断是否会出现偏差？

### 对比 case

| 行为层级 | case | 说明 | 当前状态 |
|------|------|------|------|
| A0 | 单阶段近似 case | 忽略“上平台-游览-离场-回流”的阶段转换，只保留简化起终点 | 本次补充 |
| A1 | 多阶段、均匀偏好 case | 保留阶段链，但不给定出口偏好差异，使用均匀分流 | 本次补充 |
| A2 | `case5_multistage_tour` | 多阶段 + 固定偏好参数 `p` 的完整行为层 | 已有 |

### 自变量

- 是否保留多阶段行为链
- 是否保留出口偏好差异
- 固定偏好参数 `p`
- 切换率 `kappa`

### 因变量

- 各阶段群体质量变化
- 平台关键区域滞留质量
- 各出口累计流量
- 总旅行时间近似量
- 高密度暴露时间
- 峰值密度
- 热点迁移与峰值出现时刻

### 控制变量

- 平台几何
- 起始密度
- 共享拥堵函数
- 相同数值格式与参数

### 主要输出

- 阶段/区域质量演化图
- 出口分流占比图
- 平台滞留与热点迁移图
- 行为层对比表
- 完整行为层与简化行为层的差异摘要

### 判定方式

- 若完整行为层与单阶段近似在出口负载、平台滞留或热点迁移上出现明显差异，则说明多阶段行为层必须被保留；
- 若均匀偏好与固定偏好 `p` 的输出差异显著，则说明 `p` 是需要识别的外生参数，而不是可以忽略的细节；
- 若忽略行为层后，对负载分布和风险结论的判断发生变化，则说明后续优化必须建立在完整行为评估器上。

## 7.4 G4：最优控制参数求解

### 目标

对可控参数进行 HCMBO 自动求解，回答“哪些方向配置与入口流量控制组合最优”，并与随机搜索、TPE、DE 等基线对照，说明结构感知混合分块优化相对于通用黑箱搜索的求解路径、计算预算和结果差异。

### 研究问题

1. 在给定目标函数下，自动搜索是否能找到优于人工基线的管控方案？
2. 离散方向配置 `s` 与分段入口流量控制 `q(t)` 中，哪些对结果最敏感？
3. 当 `λ1/λ2/λ5/λB/λR` 权重改变时，最优管控组合是否发生迁移？
4. HCMBO 的结构化候选生成和代理预筛选是否能够保留真实评估中的高质量候选？
5. 在相同或可报告的仿真预算下，HCMBO 与随机搜索、TPE、DE 等基线得到的最优目标值、评估次数和搜索轨迹有何差异？

### 优化变量

当前论文只优化下列可控变量：

- 离散变量 `s`
  - 受控通道状态或策略编号
  - 单条通道状态可取 `{E, W, FREE, CLOSED}`，分别对应正向单向、反向单向、双向和关闭
  - `CLOSED` 对应 $U_c(x)=\varnothing$
  - HCMBO 通过方向候选生成、方向筛选或方向内优化来搜索 `s`
- 连续/分段变量 `q(t)`
  - `q_c^+(t)` 与 `q_c^-(t)` 分别表示通道两侧入口在各时间段的流入速率上限
  - 每个通道入口的 `q(t)` 由 reference run 得到的 `qbar_by_gate` 归一化后生成
  - 搜索空间采用 $0 \le q_g^{(m)} \le \bar q_g$ 的容量比例参数化
  - `q(t)` 是当前控制问题的核心连续变量，用于直接控制入口流量，而不是改变几何引导强度

外生行为参数：

- 固定分流偏好 `p = \hat p`
  - 由历史数据或行为层实验识别后固定
  - 不作为 G4 的直接优化变量

当前暂不纳入：

- 决策区域位置 `xi`
- 分流偏好参数 `p` 的直接优化
- 完整 Pareto 前沿求解

### 优化目标

采用加权和目标：

$$
J = \lambda_1 J_1 + \lambda_2 J_2 + \lambda_5 J_5 + \lambda_B J_B + \lambda_R J_R,
$$

其中：

- `J1`：总旅行时间近似量
- `J2`：高密度暴露时间
- `J5`：通道负载方差
- `JB`：入口等待或排队惩罚
- `JR`：入口拒绝、通道绑定或流量控制副作用相关惩罚

### 求解方法

G4 及后续 V2 优化实验使用独立配置文件作为实验入口，统一声明基线仿真配置、仿真覆盖项、HCMBO 参数、对照方法、评估预算和输出目录。命令行参数仅作为临时覆盖项使用。

当前主方法采用 `methodology/optimization v2.md` 中定义的 HCMBO 思路：

1. 先运行 no-cap reference，估计各入口的参考流量上限 `qbar_by_gate`；
2. 生成方向候选 `s`，每条通道可在 `{E,W,FREE,CLOSED}` 间切换；
3. 在每个方向配置下，将入口流量曲线 `q(t)` 参数化为 `[0,1]` 区间内的比例向量；
4. 对固定方向的 `q(t)` 进行结构化候选生成，包括初始设计、LCB 式候选建议和必要的局部 polish；
5. 对候选控制向量 `z=(s,q)` 执行中保真仿真评估；
6. 从中保真候选池中选择 `top_k` 控制向量进行高保真复验；
7. 最终以高保真目标函数排序，输出最优控制、候选表和方法对比表。

对照方法包括：

1. baseline/prior 策略：不做优化或只使用先验方向和容量；
2. random search：在同一 `z=(s,q)` 空间中随机采样；
3. pure SA：在混合变量空间中做模拟退火；
4. TPE mixed BO：使用 TPE 风格混合变量优化；
5. enum-DE：枚举方向配置并对连续 `q(t)` 做差分进化或等价连续搜索；
6. HCMBO 变体：比较结构化搜索、queue-aware 评分、RF 代理和 HF top-k 选择策略。

### 对比 case

| 优化层级 | 对比对象 | 说明 |
|------|------|------|
| O0 | 人工基线策略 | 例如 `case1_baseline` 与人工指定策略 |
| O1 | 随机搜索 | 对 `s` 与 `q(t)` 做混合变量随机采样，作为预算公平基线 |
| O2 | TPE mixed BO | 对 `z=(s,q)` 做通用混合变量 BO |
| O3 | enum-DE | 枚举方向配置并优化连续流量控制曲线 |
| O4 | HCMBO 主方法 | 对 `s + q(t)` 做结构感知混合分块优化 |
| O5 | HCMBO 消融变体 | 去掉或替换 DFO、LF 筛选、queue-aware 评分、HF top-k 选择等环节 |

### 因变量

- 综合目标函数 `J`
- `J1/J2/J5/JB/JR`
- 峰值密度
- 累计通过量
- 通道负载占比
- 入口实际流量、入口拒绝量和等待峰值

### 控制变量

- 场景几何
- 网格与时间步规则
- 速度函数
- 初始密度
- 未被优化的外生模型参数默认值

### 主要输出

- 独立优化配置文件
- 最优参数配置表
- 候选策略排序表
- 不同权重下的最优解对比表
- 参数搜索日志
- HCMBO 迭代日志
- 代理排序与真实排序一致性报告
- HCMBO 与横向基线的评估次数、最优目标值和最优配置对比表

### 判定方式

- 若搜索得到的最佳方案在 `J` 上优于人工基线，则说明参数求解链路有效；
- 若不同权重下的最优参数发生迁移，则说明该问题确实存在多目标权衡；
- 若 HCMBO 在相同预算下接近或优于 TPE、random search、DE 等基线，则说明结构感知搜索具有计算优势；
- 若代理 Top-`K` 能稳定保留真实高质量候选，则说明代理预筛选可作为降低评估成本的有效环节；
- 若 `q(t)` 的变化会显著影响 `J1/J2/J5/JB/JR`，则说明入口流量控制值得作为当前正式优化框架的核心连续控制变量。

6. 结果解释应区分“优化目标值更低”和“入口拒绝/等待等安全行为更好”。

## 10.1 参数求解实验的候选范围

当前优化实验以 `z=(s,q)` 为控制变量，不再包含几何引导强度控制变量。建议范围如下：

| 参数 | 符号 | 当前候选范围 | 说明 |
|------|------|------|------|
| 策略编号 | `s` | `{baseline, six_directional_cases, one_closed_cases}`，单通道状态为 `{E,W,FREE,CLOSED}` | 离散策略集合，包含通道关闭状态 |
| 入口流量控制 | `q(t)` | 对每个入口、每个时间段取 `0 <= q_g^{(m)} <= qbar_g` | 当前连续控制变量，用于限制入口流入速率 |
| 外生分流偏好 | `p=\hat p` | 固定值，不进入 G4 搜索 | 由行为识别或 G3 设定给出，作为下层评估器输入 |
| 目标权重 | `lambda` | 若干组合，如效率优先、安全优先、均衡优先 | 用于多目标权衡分析 |

## 10.2 优化目标口径

参数求解统一使用：

$$
J = \lambda_1 \widetilde J_1 + \lambda_2 \widetilde J_2 + \lambda_5 \widetilde J_5 + \lambda_B \widetilde J_B + \lambda_R \widetilde J_R,
$$

其中 `\widetilde J_1,\widetilde J_2,\widetilde J_5,\widetilde J_B,\widetilde J_R` 可取原始量，也可在实现层做归一化后再加权。
第一阶段允许先用原始量或基于基线的相对量，只要在代码和结果表中口径一致即可。
